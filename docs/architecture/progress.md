# v2 实现进度

当前开发版本 **`2.0.0a2`**。阶段二已实现任务、持久化记录、视频和本地评测，
并在 Linux CPU / H800 CUDA 上跑通真实 Minecraft 与 VPT 发布权重的研究链路，补充了实际 GPU 渲染与轨迹行为检查。开发分支现已实现 BC 和同步 PPO 的最小训练闭环。BC 包括：原生/旧 LMDB 数据窗口、可求导 VPT、单 GPU 训练与恢复、模型重载和真实游戏采样。短训练后行为出现退化，不能作为性能提升发布。它仍是 alpha，不代表全部 v2 能力或发布门槛完成。

## 验证边界

阶段二记录为 CPU 环境 74 项、CUDA 环境 75 项测试通过，均无跳过；两个初始真实游戏 e2e 分别通过。VPT foundation 1x 在 CPU 上连续 136 帧，
覆盖 128 帧缓存，v1/v2 网络输出、确定性动作、价值与状态精确一致。
初始游戏 e2e 预算 3 步。后续 RL 2x 在 GPU 上采样 2,000 步，砍掉 16 块云杉原木并执行合成，
录像连续，但有局部急转和无效合成，未取得钻石。权重、动作对齐和行为结论详见[GPU 与轨迹行为验证](gpu-validation.md)。

此前的下载超时已定位为当前非交互进程未启用已有代理。显式传入代理后已补齐运行依赖、引擎和权重。
依赖版本、固定 revision、SHA-256 与产物路径均列在[验证记录](stage2-validation.md)。

仍需扩展其他 GPU/驱动、模型变体、操作系统、长期稳定性、任务成功率和游戏确定性验证；部分引擎统计字段的暂存补齐现象也需继续跟踪。
CI 工作流已配置但尚无远端执行结果。真实 e2e 位于 `tests/e2e`，需显式启用。

## 下一批重构范围

架构规范中的 A–E 是整体发布路线，与此次“阶段一/阶段二”增量交付不一一对应。
`a2` 推进了 B 的适配与 C 的研究闭环；开发分支现已完成 C 的一次 BC 训练更新闭环。
PPO 增量回归 CPU **89 项**、CUDA **94 项**通过，均无跳过；Ruff、格式、Pyright 与 MkDocs strict 检查通过。

后续重点转向 PPO 的持续环境、缓存重建、长任务和多种子训练验证；随后推进 Ray 和 GROOT/ROCKET/STEVE1。
BC 的原始数据时间映射与短训练退化保留为已知问题，同时继续扩展运行支持矩阵。泛化 wrappers、GUI 与复杂任务事件也需单独迁移。
稳定版 `2.0.0` 必须通过完整发布门槛，不能仅按目录搬迁完成情况发布。

## 过渡期边界

842 个原包文件的路径迁入 `src/minestudio`，旧命名空间仍保留。
新实现依赖旧代码的例外限定为 MineRL 后端和 VPT 网络组件；其他新领域不得反向依赖旧训练/分布式实现。
`models`、`simulator`、`data` 顶层采用延迟兼容导出。原生 reader/writer 与评测编排不加载 Torch 或游戏。

Pyright strict 覆盖 core/actions/envs、策略协议与 VPT 配置、rollout/CLI/tasks、原生 storage 和 evaluation。
VPT 运行时及旧网络不在当前严格类型范围内；未知第三方类型只在 MineRL 动态边界局部豁免。
pytest 默认收集 unit/integration；旧根目录实验脚本和需要游戏的 e2e 均不自动混入轻量检查。

新 CI 构建并保存产物，不部署站点。旧 Sphinx 源码保留供 v1 查阅，发布工作流保持手动触发。
