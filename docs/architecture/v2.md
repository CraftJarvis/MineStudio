## 1. 定位与确定项

MineStudio 是面向 **Minecraft 智能体研究**的 Python 工具包。主要用户是需要运行、定制、训练和评测智能体的研究者。

架构的验收目标：新增一种策略、任务或数据模态时，修改集中在对应模块；单环境实验可以直接调试；扩展到分布式执行后仍使用相同的领域协议。

| 决策 | 确定内容 |
| --- | --- |
| 项目范围 | 聚焦 Minecraft；首版保留 MineRL/Malmo 后端，通过适配层隔离实现 |
| 仓库与发行 | 单仓库、一个 `minestudio` Python 发行包、`src` 布局、按需安装 extras |
| Python | 第一方代码保持 Python 3.10 语法兼容；CI 配置覆盖 3.10–3.12，实际运行时支持以验收矩阵为准 |
| 环境接口 | 遵循 Gymnasium 的 `reset` / `step` / `close` 约定 |
| 策略接口 | 最小推理协议独立于 Torch、训练算法和分布式框架 |
| 动作边界 | 公共环境动作是具名 Minecraft 控制量；模型动作编码由显式 codec 处理 |
| 轨迹语义 | 离线数据、在线采样与评测共享时间对齐和 episode 边界约定 |
| 训练能力 | 行为克隆、actor-critic 等能力单独声明；基础策略不强制持有价值头 |
| 执行后端 | 本地执行是基准路径；Ray、Lightning 是可选适配 |
| 扩展方式 | 优先显式传入对象或工厂；不扫描并导入整个项目来完成注册 |
| 公共 API | 使用模块级公开入口和显式 `__all__`；内部文件路径不属于兼容承诺 |
| 代码工具 | Ruff 格式化与 lint，Pyright 类型检查，pytest 行为测试 |
| 文档 | Markdown 为主要内容格式；v2 采用 MkDocs Material 与 mkdocstrings 的 Python 支持 |
| 兼容重点 | 允许调整 Python API、命名和配置；已有数据与权重提供可验证的迁移路径 |

本次重构不扩展为多游戏通用框架，不拆分为微服务，也不要求所有训练流程使用同一种调度循环。未来确有独立发布或多环境需求时，再为其增加决策记录。

## 2. 术语表与命名 { #terminology }

### 2.1 统一术语

| 术语 | 中文 | 精确定义与命名约定 |
| --- | --- | --- |
| environment / env | 环境 | 暴露 Gymnasium 交互接口的对象；代码中的局部变量可写 `env` |
| backend | 后端 | 实现环境进程、协议或执行机制的适配；必须带上下文，如 `EnvBackend`、`RolloutBackend` |
| policy | 策略 | 从观测和状态生成动作的对象；基础公共接口使用 `Policy` |
| agent | 智能体 | 产品与教程中对完整行为系统的称呼；不作为 `Policy` 的另一套代码命名 |
| model / network | 模型 / 网络 | 策略内部的可训练计算组件；只有网络计算时不命名为 `Policy` |
| observation | 观测 | 环境在一个时间点提供的数据；公共参数使用全称 |
| action | 环境动作 | 具名按键与相机转动量，可直接交给 `MinecraftEnv.step()` |
| policy action | 策略编码动作 | 模型输出或训练使用的离散索引、向量或 token；变量名为 `policy_action` |
| action codec | 动作编解码器 | 在环境动作和策略编码动作之间转换，并声明量化、裁剪及规范化规则 |
| state / next_state | 策略状态 | 单条交互流的递归状态或缓存；公开接口统一使用 `state`，不再混用 `memory` |
| episode | 一局交互 | 一次 `reset` 之后到终止、截断或运行失败的交互序列 |
| transition | 单步转移 | `observation[t]`、`action[t]`、`reward[t]`、`next_observation[t]` 及结束信息 |
| trajectory | 轨迹 | 有顺序和边界信息的交互记录；逻辑结构不绑定存储格式 |
| window | 数据窗口 | 从单个 episode 选出的训练序列，可以带 padding；不暗中跨 episode |
| fragment | 采样片段 | 为在线传输或缓存切出的连续转移；切片本身不表示 episode 结束 |
| batch | 批次 | 为计算组合的数据窗口或观测；`B` 表示批量轴，`T` 表示转移时间轴 |
| task | 任务 | 初始化条件、指令、奖励和成功/失败条件的定义 |
| evaluation suite | 评测集 | 带版本的任务、种子、重复次数、预算与指标组合 |
| rollout | 采样交互 | 运行策略与环境并收集转移的过程 |
| inference | 模型推理 | 一次或一批模型计算；不用于命名整个采样子系统 |
| loss / objective | 损失 / 训练目标 | 可独立计算、测试的优化目标；不归类为生命周期 callback |
| wrapper | 环境包装器 | 显式改变环境观测、动作或交互行为的组合对象 |
| transform / processor | 数据变换 / 策略处理器 | 前者是独立数据变换；后者绑定特定策略的预处理、条件编码与输出处理 |
| callback | 生命周期回调 | 日志、录像等事件扩展；其可见数据与允许的副作用必须明确 |
| factory | 工厂 | 每次调用创建一个新对象的函数；使用 `env_factory`、`policy_factory` |
| generator | 生成器 | 使用迭代协议持续产生数据的对象；不用于命名普通工厂函数 |
| modality | 模态 | 图像、动作、文本等数据类型；统一使用 `modality`，不用 `modal` |
| checkpoint | 训练检查点 | 可用于恢复训练的状态，包括优化器等；与仅用于推理的模型导出区分 |
| run | 实验运行 | 一次训练、采样或评测调用及其配置、日志、产物，具有 `run_id` |

### 2.2 旧名称的处理方向

以下是迁移目标，不意味着机械的一对一重命名。

| v1 名称 | v2 目标 | 迁移要求 |
| --- | --- | --- |
| `simulator` / `MinecraftSim` | `envs` / `MinecraftEnv` | 拆出引擎管理、原生动作适配和 wrappers |
| `models` / `MinePolicy` | `policies` / `Policy` | 分离最小协议、Torch 实现和训练能力 |
| `get_action()` | `act()` | 输入输出和状态约定按本文统一 |
| `state_in` / `state_out` / `memory` | `state` / `next_state` | 单环境状态由调用者持有 |
| `MineGenerator` | `RolloutRunner` 及其内部 collector | 拆开交互、执行后端和记录职责 |
| `inference` | `rollout` | 模型推理留在策略模块内部 |
| `offline` / `online` | `training.offline` / `training.online` | 共享目标和数据约定，保留各自训练循环 |
| `MineLightning` | `LightningPolicyModule` | 位于 `integrations.lightning`，不充当核心策略接口 |
| `BehaviorCloneCallback` | `BehaviorCloningLoss` | 保留或修改损失归约方式都必须通过数值对照说明 |
| `RawDataset` | `TrajectoryDataset` | 普通数据读取不导入 Lightning |
| `EventDataset` | `EventWindowDataset` | 明确事件筛选与窗口定位规则 |
| `ModalKernelCallback` | `ModalityCodec` 与窗口变换 | 按解码、切片、padding 等职责拆分 |
| `KernelManager` | 存储 reader 与窗口索引 | 不把下载、读取、划分和绘制继续集中在同一管理器 |
| `env_generator` / `policy_generator` | `env_factory` / `policy_factory` | 保证多 worker 调用产生独立资源 |
| `GrootPolicy` / `RocketPolicy` / `SteveOnePolicy` | `GROOTPolicy` / `ROCKETPolicy` / `STEVE1Policy` | 公共类名与论文缩写统一；`VPTPolicy` 保留 |

模块和文件使用 `snake_case`，类使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`。模型目录使用 `vpt`、`groot`、`rocket`、`steve1`；具体架构版本写入配置及模型 manifest，不用 `one`、`new`、`final` 等目录后缀区分实验。

公开配置使用 `sequence_length`、`learning_rate`、`num_envs`、`num_workers`、`data_dir`、`output_dir`、`checkpoint_path` 等完整名称。局部数学公式允许 `x`、`t`、`log_prob` 等领域惯用名；公共接口不使用 `hiddim`、`win_len`、`cfg`、`kwargs` 来隐藏参数含义。

### 3.2 依赖约束

| 模块 | 可以依赖的项目模块 | 约束 |
| --- | --- | --- |
| `core` | 无 | 只依赖标准库与 NumPy；不放模型、存储客户端或框架工具 |
| `actions` | `core` | 编码实现可通过私有适配使用 `_vendor`；不得依赖策略或环境进程 |
| `tasks` | `core`、`actions` | 通过任务上下文接口操作世界；不导入具体 `MinecraftEnv` 或 MineRL 类 |
| `envs` | `core`、`actions`、`tasks` | 不依赖策略、数据集、训练或 Torch |
| `policies` | `core`、`actions` | 不依赖 `training`、`rollout`、`envs`；输入规格由 processor 检查 |
| `data` | `core`、`actions` | 不依赖环境进程、策略实现、Lightning 或 Ray |
| `rollout` | `core`、策略/环境协议、记录协议 | collector 不直接写某种存储或调用某个训练器；存储记录适配可调用 `data` |
| `training` | 策略能力、`data`、`rollout` 协议 | 训练目标不导入 Ray、Lightning、W&B 或具体环境实现 |
| `evaluation` | `tasks`、`rollout` 及策略/环境协议 | 不需要构造训练器即可评测 |
| `integrations` | 被适配模块的接口与基础组件 | 框架细节局限在各自适配器内 |

CLI、`rollout.api`、`training.*.api`、`evaluation.api` 是组合入口，可以在用户选择后延迟加载适配器。核心循环只接收适配器实例，不反向导入这些入口。对依赖的检查必须区分组合入口和领域实现，不能用任意位置的延迟导入掩盖反向依赖。

`core` 只容纳两个以上领域确实共享且语义稳定的类型。张量树操作留在 `policies.state`，路径与缓存逻辑留在其资源所属模块。第一方代码不再增加没有明确领域归属的顶层 `utils`、`common`、`misc`、`temp` 或 `body` 模块。

`PolicyBatch` 与策略计算输出归属 `policies.batches`；`training.batches` 负责从轨迹窗口构造它们。策略协议不能为了获得 batch 类型而反向导入训练模块。`Environment` 是 runner 使用的公共交互协议，`EnvBackend` 是 `MinecraftEnv` 使用的底层引擎协议，两者不能混用。

第三方上游能直接依赖时使用正常依赖；必须维护的 fork 记录来源 URL、固定 revision、许可证和本地补丁。`_vendor` 不属于公共 API，也不参加全仓格式化；第一方代码通过少量适配点访问它。

### 3.3 安装与导入

| 安装组合 | 提供的能力 |
| --- | --- |
| `minestudio` | 轻量类型、配置/manifest 基础操作、CLI 帮助与诊断入口 |
| `minestudio[envs]` | Gymnasium 环境及默认 MineRL 适配所需的 Python 依赖 |
| `minestudio[data]` | LMDB、视频等数据读取与转换 |
| `minestudio[policies]` | Torch 策略基础与 VPT 路径；其他模型专属依赖按对应 extras 增加 |
| `minestudio[train]` | 离线/在线训练基础、Torch 与数据依赖；Lightning 留在 legacy extra，不隐式要求 Ray |
| `minestudio[distributed]` | Ray 执行适配；与任务所需的其他 extras 组合安装 |
| `minestudio[gui]` | 可选交互窗口；不与 headless OpenCV 安装互相冲突的发行包 |

公共 extras 使用 v2 名称 `envs`、`policies`，取代早期讨论中的 `simulator`、`models` 草案名称。实际依赖版本在首个安装矩阵验证时锁定；包元数据声明已验证的兼容范围，实验与 CI 环境另外保存精确约束。

必须满足：`import minestudio` 与导入 `Policy` 协议不加载 Torch、Ray 或 Lightning；导入某个策略家族不导入其他家族；读取数据不要求 Java、GPU 或游戏引擎。公共 re-export 使用显式映射实现按需加载，不依赖导入副作用注册。

Java、渲染系统依赖和引擎资源由安装文档、`doctor` 与资源准备命令负责。普通 import、数据集构造和环境构造不能进行交互式确认或隐式下载。

## 4. 数据、动作和边界契约

### 4.1 观测与动作

默认观测是字典，`image` 为 RGB、`uint8`、`[H, W, 3]`，像素范围为 0–255。环境的 observation space 必须描述实际返回字段。增加指令、分割等字段时，同时增加模态规格；第三方扩展使用带命名空间的字段，避免覆写已有字段。

公共环境动作使用以下逻辑结构；这是 v2 相对 v1 的显式格式变化：

```python
from typing import TypedDict

import numpy as np
from numpy.typing import NDArray


class Observation(TypedDict):
    image: NDArray[np.uint8]


class MinecraftAction(TypedDict):
    buttons: dict[str, int]
    camera: NDArray[np.float32]
```

`buttons` 包含动作规格声明的具名按键，值为 0 或 1；基础词表包括 `attack`、`back`、`forward`、`jump`、`left`、`right`、`sneak`、`sprint`、`use`、`drop`、`inventory` 与 `hotbar.1` 至 `hotbar.9`。`camera` 为 `[pitch_delta, yaw_delta]`，形状 `[2]`，单位为每次动作施加的角度，不是速度或模型 bin 索引；具体范围与后端支持情况由 `ActionSpec` 声明。

环境接收完整的规范化动作。`noop_action()` 返回全部释放的按键与零相机增量。后端不能支持某个非零控制量时必须报错，不能静默丢弃。`step()` 不修改调用者传入的动作。

`Policy.act()` 必须返回上述环境动作。VPT 的相机 no-op 索引 `60`、按键组合空间大小 `8641` 等编码约定不进入通用环境协议；预处理、策略编码与动作解码由策略 adapter/processor 显式执行。

`ActionCodec` 必须记录标识、版本、按键规则和相机量化配置。`decode(encode(action))` 可能因量化或按键规范化而有损，测试应检查规定的误差与规范化结果，不能假设它是无损恒等变换。原始数据保留原始动作；编码的表示能力、有效 mask 和损失权重分别声明。

### 4.2 时间对齐与窗口

```text
observation[t] -- action[t] --> observation[t+1]
                             reward[t]
                             terminated[t], truncated[t]
```

一个长度为 `T` 的完整窗口包含 `T` 个动作、奖励和结束标志，以及 `T+1` 个观测。episode 内的 `step_index` 从 0 开始，记录转移起点；`timestamp` 只用于带单位的实际时间，不能代指数组下标。环境采样频率、动作重复次数、视频编码帧率分别记录。

`TrajectoryWindow` 至少暴露以下字段；存储层可以列式存放，无需逐步创建 Python 对象：

| 字段 | 形状 / 语义 |
| --- | --- |
| `episode_id`, `start_step` | 单个 episode 的身份和窗口起点 |
| `observations` | 各模态的 `[T+1, ...]` 数据，或等价的有序表示 |
| `actions` | `T` 个原生环境动作 |
| `rewards` | `[T]` 浮点数，配套 `reward_mask` 表示是否已知 |
| `terminated`, `truncated` | `[T]` 布尔值，配套 `boundary_mask` 表示是否已知 |
| `valid_mask` | `[T]`，表示真实存在的转移，不承担模态缺失或训练权重的含义 |
| `observation_mask` | 各模态 `[T+1]`，区分实际观测、缺失与补齐内容 |
| `action_mask` | `[T]`，表示动作标签是否可用 |
| `first_mask` | `[T]`，表示该转移起点是否为 episode 初始观测；窗口起点不自动视为 episode 起点 |

规则：

1. train/validation/test 先按 episode 或来源组划分，再生成窗口；禁止由重叠窗口造成数据泄漏。
2. 普通窗口不跨 episode。尾部补齐必须有 mask，不能伪造奖励、结束标志或有效观测。
3. 事件窗口明确事件锚点、前后偏移与边界裁剪策略；不在 reader 中隐藏固定时间过滤规则。
4. `PolicyBatch` 是训练专用表示，采用 `[B, T, ...]`；从窗口到 batch 的转换负责 dtype、device、模态对齐和策略编码。
5. recurrent 训练必须显式选择起始状态：连续窗口携带状态、带 burn-in 重建状态，或声明截断序列近似。不能靠相邻 timestamp 猜测属于同一 episode。
6. 前一动作由同一 episode 的真实前驱取得；episode 起点和窗口起点不能混淆。
7. reader/writer 的逻辑契约独立于 LMDB、视频文件和在线缓存；首版继续支持现有 LMDB 读取，通过适配器转换。
8. 窗口 `stride` 只表示窗口起点间距，不表示视频帧下采样。时间下采样必须显式定义区间内的动作、奖励和边界聚合，不能只隔帧取观测后沿用单步转移标签。

### 4.3 结束、故障与策略状态

| 情况 | 表达与处理 |
| --- | --- |
| 游戏或任务定义的终态 | `terminated=True`，停止该 episode |
| 外部步数/时间预算到达 | `truncated=True`，记录原因并保留最后观测 |
| 同一步同时命中终态与预算 | 可以同时为 True；价值 bootstrap 按终态处理 |
| 仅切出一个 fragment | 不修改 episode 的结束标志 |
| 环境崩溃、超时且结果未知 | 抛出类型化运行异常；记录失败 attempt，不伪造成功转移或终态 |
| 终止/截断后的下一次交互 | 必须显式 `reset()`，基础环境不自动 reset |

actor-critic 在已知终态后不 bootstrap；纯时间截断可从真实最后观测 bootstrap，具体算法策略必须显式配置。基础采样实现不允许将新 episode 的 reset 观测误用为旧 episode 的最后观测。历史数据的结束原因未知时标记为未知；可以用于满足条件的 BC 样本，但不能直接用于需要完整边界的 PPO/GAE。

每个环境拥有独立 `state`。episode reset、失败恢复和显式取消之后重置对应状态；批量推理只重置相关流。策略对象不得用 `self.vpred`、`self.cache_latents` 等共享可变字段向训练器传递某一步输出。需要训练统计时，返回明确的结果对象。

返回给调用者或记录器的数据不能因后续 step 被底层复用缓冲区悄悄改变。跨进程传输、零拷贝视图或状态缓存必须声明所有权和有效期，必要的快照在边界处完成。

### 5.1 环境

公开入口：`minestudio.envs`。

```python
from dataclasses import dataclass, field
from typing import Literal

from minestudio.core import MinecraftAction, Observation, StepInfo
from minestudio.tasks import TaskSpec


@dataclass(frozen=True)
class ImageSize:
    height: int
    width: int


@dataclass(frozen=True)
class EnvConfig:
    backend: Literal["minerl"] = "minerl"

    def __init__(
```

### 5.2 策略与能力

公开入口：`minestudio.policies`。

```python
from typing import Protocol, TypeVar

from minestudio.core import MinecraftAction, Observation

StateT = TypeVar("StateT")


class Policy(Protocol[StateT]):
    def initial_state(self) -> StateT: ...

    def act(
        self,
        observation: Observation,
        state: StateT | None = None,
        *,
        deterministic: bool = False,
    ) -> tuple[MinecraftAction, StateT]: ...
```

`None` 输入表示为一条新交互流初始化状态；无状态策略的输入输出状态均为 `None`。`initial_state()` 只处理单流，批量状态布局由可选 adapter 管理，不能在基础协议中假定状态是特定形状的张量列表。

| 可选能力 | 契约 |
| --- | --- |
| `BatchedPolicy` | `act_batch(observations, states, *, deterministic=False)` 接收等长序列，返回顺序一致的 actions 与 next states |
| `TorchPolicy` | 可组合基础实现和标准 `.to()` / `.eval()`；不默认创建动作头或价值头 |
| `LikelihoodPolicy` | `evaluate_actions(batch: PolicyBatch, state=None)` 返回 `ActionEvaluation`，用于计算给定编码动作的 log probability；其他模型可提供独立的自定义训练目标 |
| `ActorCriticPolicy` | `act_with_stats(observation, state=None, *, deterministic=False)` 返回 `ActorCriticStep` 与 next state；`evaluate_actions()` 返回包含 value 的 `ActorCriticEvaluation` |
| 模型导出 | `save_pretrained(path)` / `from_pretrained(source, *, revision=None)` 使用带版本的 manifest |

`PolicyBatch` 包含模型输入、编码动作、`valid_mask` 与 `first_mask`，不持有优化器或运行后端对象。`ActionEvaluation` 至少包含 `[B, T]` 的 log probability 和 next state；按目标需要提供 entropy 等额外输出。`ActorCriticEvaluation` 还包含同形状的 value。给定的 state 与 batch 时间起点对齐，默认不保存在策略实例中。

`ActorCriticStep` 至少包含环境 `action`、实际采样的 `policy_action`、行为 `log_prob` 和 `value`；next state 单独返回。value 以实际回报尺度表达，内部使用归一化价值头的策略负责转换并记录归一化状态。批量统计采样可以由专门 adapter 实现，不能通过读取策略实例上的“最近一次输出”拼装。

PPO 只接受声明 actor-critic 能力的策略。其概率对应实际采样的编码动作，不能通过有损的环境动作反向编码后重新猜测。rollout 额外记录 `policy_version`、状态来源版本和行为统计；这些字段属于训练扩展记录，不改变通用轨迹格式。

首版 PPO 以冻结行为策略的采样轮次为基准。权重切换、状态延续和允许的样本陈旧程度必须显式定义并测试；异步 Ray 调度不能隐式改变算法语义。

最小交互示例：

```python
from minestudio.envs import MinecraftEnv
from minestudio.policies import VPTPolicy

policy = VPTPolicy.from_pretrained("./artifacts/vpt")
policy.to("cpu").eval()

with MinecraftEnv() as env:
    observation, info = env.reset(seed=42)
    state = None

    for _ in range(100):
        action, state = policy.act(observation, state, deterministic=True)
        observation, reward, terminated, truncated, info = env.step(action)
        if terminated or truncated:
            break
```

这段手动循环用于演示接口，不承诺采集完整 episode；需要记录预算截断与结果时使用 `RolloutRunner`。Torch 的 `act()` 不构造梯度图，训练入口另行使用可求导的训练能力；基础 `Policy` 不要求 `.to()` 或 `.eval()`。

模型相关的图像归一化、尺寸适配、文本 tokenizer 和动作 codec 由同一 processor 定义，同时服务训练和推理。checkpoint 必须保存 processor 配置，加载时检查输入规格，不能靠散落在教程中的预处理来补全模型定义。

`from_pretrained()` 接收本地模型导出目录，或显式指定的远程模型身份。使用远程身份是下载入口，必须把解析后的固定 revision 和文件摘要记录在本地 manifest；普通策略构造不自行联网。模型导出与包含优化器状态的训练 checkpoint 使用不同的格式标识。

### 5.3 数据

公开入口：`minestudio.data`。

```python
from pathlib import Path
from typing import Literal

from minestudio.core import TrajectoryWindow


class TrajectoryDataset:
    def __init__(
        self,
        path: str | Path,
        *,
```

### 5.4 任务

公开入口：`minestudio.tasks`。

`TaskSpec` 是可序列化的不可变配置，`TaskRuntime` 是每个环境独立的可变执行状态。任务逻辑依赖领域上下文和游戏事件，不直接操作训练器或 Ray actor。

```python
from dataclasses import dataclass
from pathlib import Path

from minestudio.tasks import EndRule, InitializationRule, RewardRule


@dataclass(frozen=True)
class TaskSpec:
    id: str
    version: str
    instruction: str
    initialization: tuple[InitializationRule, ...] = ()
    rewards: tuple[RewardRule, ...] = ()
    success: tuple[EndRule, ...] = ()
    failure: tuple[EndRule, ...] = ()
    max_episode_steps: int | None = None

    @classmethod
    def from_yaml(cls, path: str | Path) -> "TaskSpec": ...
```

规则必须是带类型与版本的配置，而非 YAML 中嵌入的任意 Python 对象。首版统一：初始化按列表顺序执行；任务奖励与后端奖励相加并分别记录贡献；success 与 failure 各组内采用任一规则命中；同一步同时命中时 failure 优先。需要复合条件或替换奖励时使用显式组合规则或 wrapper，不能隐式覆盖后端奖励。

任务终态产生 `terminated`，步数预算产生 `truncated`。单局的成功标志写入结果，奖励不作为成功的替代判断。评测可以明确覆写预算，但必须保存最终解析的 TaskSpec 和覆写来源。

`2.0.0a2` 具体规则为 `command@1`、`metric_change@1`、`metric_threshold@1`。
初始化全部完成后才建立奖励/相对阈值基线并交付 obs0；不把初始化命令记为策略 transition。
数值指标从 info 路径读取，缺失默认报错。显式 `missing="zero"` 仅容许现有父映射中的末级键缺失。
结束条件从第一个有效 step 起计算；指令目前作为元数据保留，不自动改变策略输入。

### 5.5 采样与记录

公开入口：`minestudio.rollout`。

```python
from dataclasses import dataclass
from typing import Literal


@dataclass(frozen=True)
class RolloutConfig:
    backend: Literal["local", "ray"] = "local"
    num_envs: int = 1
    num_episodes: int = 1
    max_episode_steps: int = 1200
    seed: int = 0
    deterministic: bool = False
    max_retries: int = 0
```

`RolloutRunner(env_factory, policy_factory, config=None, *, recorders=(), cases=None)` 创建并拥有工厂返回的资源，支持上下文管理；`collect()` 返回结构化 `RolloutResult`。工厂均为无参数 callable；需要配置时用具名工厂对象或 `functools.partial`。Ray 工厂不能捕获已经启动的环境、设备上下文或进程句柄。

本地模式不初始化 Ray。记录器通过 `on_episode_start`、`on_reset`、`on_transition`、`on_episode_end` 接收数据；存储 reader/writer 位于 `data`，记录器负责调用它们。模型预测、过滤、视频编码和持久化不再集中在同一个 worker 类中。

`RolloutResult` 必须记录请求数量、完成数量、失败数量、取消数量，以及每个 episode 的身份、步数、回报、成功标志和结束原因。预算到达时显式截断；任务预算和采样预算同时存在时取较早到达者并记录原因。重试使用稳定的 case 身份和新的 attempt 身份；未知是否执行成功的单步动作不能直接重放。

`num_episodes` 是整次 run 的全局 case 数，不是每个 worker 的配额；`num_envs` 是最大并发环境数。种子按稳定 case 索引派生，不能因 worker 数量、完成顺序或重试而变化。默认遇到失败将该 case 计为失败后继续其他 case；仅配置允许的重试可以创建新 attempt。

```python
from minestudio.envs import MinecraftEnv
from minestudio.policies import VPTPolicy
from minestudio.rollout import RolloutConfig, RolloutRunner


def make_policy() -> VPTPolicy:
    return VPTPolicy.from_pretrained("./artifacts/vpt").to("cpu").eval()


with RolloutRunner(
    env_factory=MinecraftEnv,
    policy_factory=make_policy,
    config=RolloutConfig(num_episodes=2, max_episode_steps=100, seed=42),
) as runner:
    result = runner.collect()
    print(result.completed, result.failed)
```

`2.0.0a2` 的 `RolloutCase` 可显式指定准确种子和每个 case 的环境工厂；与派生种子路径共享重试语义。
记录器由调用方管理，Runner 只拥有工厂产生的环境和策略。`on_episode_start` 在 reset 前触发，
`on_reset` 只在得到有效首帧后触发。记录器异常会中止运行；其他有效前缀尽量落盘，不重试写入故障。

原生轨迹使用 `minestudio.trajectory` schema 1；每个 attempt 一个目录，NPY 保存 T+1 帧，JSONL 逐步提交转移。
completed 必须有真实边界，失败/取消保留部分记录。中断恢复必须显式启用，只读取已提交前缀。
格式字段与验证要求见[产物格式](artifact-formats.md)。视频通过独立 FFmpeg 记录器输出，不充当无损数据源。

### 5.6 训练与评测

当前 BC / PPO 公开入口为 `minestudio.training`，实现分别位于 `training.bc` 和 `training.ppo`；未来按需要拆分 `training.offline` / `training.online`。评测入口为 `minestudio.evaluation`。

首轮实现支持 VPT 的独立窗口 BC、固定划分数据、FP32 / BF16、优化器步边界恢复与推理导出。它明确采用截断上下文近似；BC 的连续流 TBPTT、burn-in、梯度累积和 scheduler 尚未实现。详见 [BC 指南](../guides/behavior-cloning.md)。

首版 PPO 支持单设备 FP32 和同步本地环境，保存行为编码动作、log probability、价值和版本化缓存，以有效步数加权累积连续序列梯度。更新前验证概率比接近 1；每轮更新后重置环境，训练序列起点使用 detached 行为缓存，属于显式的 truncated-BPTT 近似。价值归一化统计冻结，GAE 与价值损失使用奖励尺度。checkpoint 位于整轮边界，不保存游戏世界。详见 [PPO 指南](../guides/ppo.md)。

| 入口 | 责任与返回值 |
| --- | --- |
| `train_bc(policy, dataset, *, config: BCConfig)` | 验证监督训练能力，执行 BC；返回 `TrainingResult` |
| `train_ppo(policy_factory, env_factory, *, config: PPOConfig)` | 验证 actor-critic 能力，组合采样与 PPO；返回 `TrainingResult` |
| `evaluate(policy_factory, *, suite: EvaluationSuite, env_factory, config: EvaluationConfig)` | 按固定任务/种子/预算执行；返回 `EvaluationResult` |

训练配置分别归属算法、数据、优化、运行资源和日志。禁止构建要求所有算法接受相同可选参数的大型基类。`BehaviorCloningLoss` 等目标返回 `LossOutput(loss, metrics)`；参数或样本加权、有效 token 归约与损失尺度必须在配置/文档中明确，不能借风格重构默默改变数值语义。

`train_bc` 使用调用者提供的策略与 Dataset，不关闭外部 Dataset；它负责关闭自身创建的 worker、日志器等资源。基于 factory 的训练/评测入口负责关闭自己创建的实例。

`TrainingResult` 至少包含 `run_id`、解析后的配置路径、最后 checkpoint、模型导出路径与主要指标。训练 checkpoint 记录优化器、调度器、随机状态、数据进度及可恢复范围；进程恢复与“从相同游戏状态继续”是不同能力，必须分别声明。

`EvaluationSuite` 保存任务版本、种子、重复次数、预算和指标口径。评测用的 `env_factory` 接收具名参数 `task: TaskSpec`，为每个 case 创建相应环境；这是对采样/训练无参数工厂的显式扩展，不能忽略 suite 中的任务定义。预算覆写写入最终 case 配置。

评测冻结模型与 processor revision。成功率默认使用成功的有效完成 case 数除以有效完成 case 数，同时必须报告 `completed/requested`、失败原因及失败 case；无有效完成 case 时成功率为未定义，不能写 0 或 100%。重试不能重复计入分母，原始 attempt 仍然保留。

`2.0.0a2` 评测报告采用 `minestudio.evaluation` schema 1。执行前保存完整配置和 resolved cases，
执行后保存所有 attempts 与逐 case 最终结果。自动记录器随 evaluate 关闭，外部传入的记录器仍由调用方关闭。
异常报告不能覆盖引发中止的原异常。策略身份在 Python API 中是调用方声明；CLI 绑定本地 VPT manifest 摘要。

视频/VLM judge 输出独立评分与 judge 的模型、prompt、采样配置版本，不覆盖任务的确定性成功判定。

### 5.7 CLI 与扩展

`2.0.0a2` 已实现的公共 CLI：

```console
minestudio --version
minestudio doctor
minestudio engine install ./engine.zip --sha256 EXPECTED_SHA256
minestudio task collect_oak_log
minestudio trajectory ./runs/RUN/ATTEMPT
minestudio convert-vpt --config ./v1-config.json --weights ./weights.safetensors --output-dir ./vpt
minestudio evaluate --task collect_oak_log --policy ./vpt --output-dir ./runs --seeds 42 43
```

CLI 是 Python API 的组合层。引擎安装只处理显式提供的本地归档；远程资源解析、训练命令和通用数据集检查仍待后续阶段。
当前评测直接接收明确参数，尚未提供 `evaluate --config`。CLI 参数与已实现 API 的一致性优先于占位命令。

新增策略实现 `Policy` 和所需能力；新增任务实现规则；新增模态实现 codec/规格；新增训练目标实现 `LossOutput` 契约。扩展可以从用户项目显式 import 后传入，不要求修改 MineStudio 内置全局 registry，也不依赖当前工作目录的 `sys.path` 修改。

## 6. 代码与配置规范 { #code-style }

### 6.1 格式与类型

- UTF-8、4 空格缩进、100 字符目标行宽、双引号；文件保留一个末尾换行。
- 公共函数、方法和配置字段必须标注类型；使用 `list[T]`、`dict[K, V]`、`T | None` 等 Python 3.10 写法。
- 类型名必须反映数据语义。形状、dtype、设备与时间轴约定写在类型或接口文档中，不能只有 `dict[str, Any]`。
- 开放模态 payload、第三方边界确需 `Any` 时局限在边界，并在进入计算前验证/收窄；禁止为了通过检查全局关闭错误。
- 可配置集合使用 dataclass 与 `default_factory`；函数不使用可变默认参数。
- 公共对象用小型 `Protocol` 表达能力，使用 dataclass/TypedDict 表达数据；只有复用实现确有价值时引入继承。
- `__init__.py` 只处理公开导出与必要的惰性加载；不遍历目录、不启动服务、不打印日志。
- 不保留日期、作者、绝对路径和修改历史文件头；许可证、必要来源说明与简洁模块文档保留。

目标工具配置如下。迁移到 `src` 时写入项目配置，不能直接套用到尚未迁移的 v1 全树。

```toml
[tool.ruff]
target-version = "py310"
line-length = 100
extend-exclude = ["src/minestudio/_vendor", "third_party"]

[tool.ruff.lint]
select = ["E4", "E7", "E9", "F", "I", "UP", "B", "SIM", "RUF"]

[tool.ruff.format]
quote-style = "double"
indent-style = "space"

[tool.pyright]
pythonVersion = "3.10"
typeCheckingMode = "strict"
include = ["src/minestudio"]
exclude = ["src/minestudio/_vendor"]
```

第三方 stubs 或动态框架的例外逐项配置、附理由；不为继承历史实现的便利而放宽所有新模块。

### 6.2 错误、资源与副作用

- 用户输入和运行条件使用 `ValueError`、`TypeError` 或领域异常验证；`assert` 只用于内部不变量和测试。
- 跨层异常保留原因：`raise EnvironmentStartupError(...) from exc`。库不调用 `exit()`，不吞掉异常后返回看似成功的数据。
- 使用模块级 `logging.getLogger(__name__)`；CLI 决定展示和日志配置。库 import 不输出环境变量或改变 root logger。
- 文件使用 `pathlib.Path`，公开路径接受 `str | Path`，配置中的相对路径以配置文件目录解析。仓库内不写个人机器绝对路径。
- 网络访问、资源下载、device 选择、进程创建均有显式入口和可观察结果；库不自动选择某块 GPU。
- 具有外部资源的对象提供 `close()` 和上下文管理；明确创建者负责关闭，确保异常情况下也执行清理。
- 全局可变配置与共享随机种子不能作为模块间通信机制；每个 run/worker 使用明确配置和派生 seed。
- 超时、取消、重试和资源上限由运行配置声明。Ray 传输对象须具备明确序列化和所有权规则。

### 6.3 配置与产物

配置分组为 `env`、`policy`、`data`、`algorithm`、`runtime`、`logging`，对应具名类型。未知键直接报错；不通过 `**unused_kwargs` 忽略拼写错误。嵌套配置按 dataclass/schema 解析，最终配置与显式 CLI 覆写一起写入 run manifest。

每个 run 的产物至少具有如下逻辑组成：

```text
output_dir/
├── run.json                 # run_id、版本、开始/结束状态、资源与来源
├── config.resolved.yaml     # 完整解析配置
├── metrics.jsonl            # 带步骤与时间含义的结构化指标
├── checkpoints/             # 恢复训练所需状态
└── artifacts/               # 模型导出、轨迹、录像或评测明细
```

大型数据和权重存放在用户指定输出/缓存目录，不进入源码包。writer 使用可识别的临时产物与完成标记，reader 不把未完成写入视为有效数据。

## 7. 文档、示例与公共接口管理

代码标识符、公共 docstring 和主要开发者文档使用英文；本文作为中文设计基线保留。面向用户的中英文页面按稳定路径对应，缺失翻译时明确回退，不显示过期翻译为当前版本。

公共 docstring 统一采用 Google 风格，说明用途、参数约束、返回值、错误和必要示例。张量形状、动作单位、episode 边界与副作用必须有明确说明。不要重复类型标注或逐行解释显然的代码。

文档主导航为快速开始、操作指南、核心概念、实验配方、API、帮助与迁移。教程包括目标、前置条件、资源需求、步骤、预期输出与下一步。API 页只覆盖稳定公开入口，并链接最小示例与概念说明；不自动暴露 `_vendor` 或所有内部成员。

示例从 `examples` 或 `recipes` 的可运行文件引用；完整实验放 `recipes`，手动演示不伪装为 `tests/test_*.py`。首页、安装路径和一个 API 页面先完成样板，验证代码引用、搜索、深色模式、移动端和旧 URL 跳转后再迁移全站。v1 的 `docs/source` 在旧文档归档与链接映射完成前保留。

包版本以发布元数据为唯一来源，文档读取同一版本；API 文档支持静态解析或最小依赖构建，不启动 Minecraft、GPU 或分布式集群。

## 8. 版本、兼容与迁移

### 8.1 独立版本

包版本、轨迹 schema 版本、checkpoint schema 版本、任务版本和评测集版本分别维护。v2 包的第一份原生轨迹 manifest 可使用 `format="minestudio.trajectory"`、`schema_version=1`；这里的 1 不代表 v1 包格式。

| 产物 | 必须记录的信息 |
| --- | --- |
| 轨迹 manifest | 格式/schema、episode 身份、模态/动作规格、采样频率、缺失字段、来源和 split |
| 模型导出 | 模型家族与架构版本、权重摘要、processor、codec、输入规格、格式/schema |
| 训练 checkpoint | 模型导出信息及优化器、调度器、随机状态、数据进度、可恢复范围 |
| 实验/评测 | 包与源码 revision、环境/引擎 revision、任务/评测集版本、种子、配置、模型身份 |

### 8.2 迁移策略

1. v1 主线保留维护与文档入口；v2 在独立开发分支推进。
2. 首先整理公共 API、数据格式与已发布权重清单，并冻结代表性输入/输出样本。
3. 新实现落入 `src/minestudio` 后，同一 checkout 只保留一个可安装的 `minestudio` 包根。旧实现移至明确的私有 legacy 区或通过分支对照，不能同时让根目录与 `src` 下同名包参与 import。
4. 原有 LMDB 与权重通过显式 reader/converter 接入。不能可靠推断的配置、结束标志或模态信息写成缺失项，不猜测补齐。
5. 权重转换输出 key 映射与未匹配项报告，使用固定输入对照 logits、value、状态和确定性动作；误差阈值预先按 dtype/模型登记。
6. 旧 API 只在语义等价时提供薄别名和弃用提示；动作格式或返回语义变化使用明确的 legacy adapter，不默默兼容两套含义。
7. `2.0.0` 发布前冻结公开导出清单、支持矩阵与迁移指南。稳定公开 API 的破坏性变更需要后续主版本；实验接口放明确的 experimental 命名空间并标注。

v2 骨架接入时一并修正 setuptools 的包发现、资源打包和 CLI entry point。必须从构建出的 wheel 安装后运行检查，不能只验证仓库中的 editable import。

## 9. 实施阶段与验收 { #acceptance }

### 9.1 实施顺序

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：行为基线 | 公开 API/权重/数据清单、固定样例、动作和边界回归 | 能分辨重命名与行为变化；基线输出已保存 |
| B：基础骨架 | `src`、依赖拆分、core/actions/envs/policies、资源诊断 | 本地单环境 VPT 路径可运行，最小安装组合通过 |
| C：研究闭环 | 轨迹记录/读取、BC、模型导出/加载、任务与评测 | 同一套 processor/codec 跑通采样 → 数据 → 一次更新 → 评测 |
| D：能力迁移 | PPO、Ray、其余基线策略、模态与任务扩展 | 算法语义、状态隔离、故障与恢复路径完成对照 |
| E：发布 | 文档、迁移工具、wheel、版本与支持矩阵 | 所有发布门槛通过，再发布 `2.0.0` |

`2.0.0` 的基线能力包括 VPT 的运行/数据/BC/PPO/评测闭环，以及 GROOT、ROCKET、STEVE-1 在已声明版本范围内的权重加载和推理。模型是否支持 BC、PPO、条件输入或批量推理必须逐项列入能力矩阵，不由继承关系暗示。

### 9.2 必须具备的检查

| 检查 | 验证内容 |
| --- | --- |
| 格式、类型和依赖方向 | Ruff、Pyright、明确的 import 边界规则；只检查已迁移的第一方代码 |
| 动作契约 | 按键词表、相机单位、量化误差、no-op、规范化与 codec 版本 |
| 轨迹契约 | `T/T+1` 对齐、padding、模态缺失、split 不泄漏、上一动作与事件窗口 |
| 环境契约 | spaces 一致、seed 传播、终止/截断区分、无自动 reset、close 幂等 |
| 策略契约 | 单流/批量一致性、多环境状态隔离、训练与推理 processor 一致、能力检查 |
| 算法契约 | BC 数值归约、PPO 行为概率、GAE 终态/截断 bootstrap、状态来源版本 |
| 数据与权重兼容 | 代表性旧数据读取对照、权重转换数值对照、未知信息不被伪造 |
| 运行故障 | worker/环境异常、取消、重试计数、失败 attempt 保留与资源清理 |
| 安装与打包 | 各 extras 的最小 smoke、wheel 内子包与资源完整、从任意工作目录导入 |
| 文档 | 严格构建、内部链接与旧 URL 映射、公共示例、版本一致性、移动端阅读 |

普通 PR 运行不需要游戏引擎的 unit、契约和打包检查；受影响的集成检查按环境运行。真实 Minecraft、GPU 模型和 Ray 的 e2e 使用明确 marker 与资源配置，发布前必须完成并保存结果。

吞吐、启动时间、显存和采样正确性在固定模型、输入、硬件和引擎配置下与 v1 对照。首先记录可复现基线，再登记允许误差/回归预算；性能结论不能来自不同配置下的数字比较。
